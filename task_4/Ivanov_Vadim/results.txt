Задание 4. Метод Монте-Карло

Вычисляется интеграл x^2 на [0,1], точное значение 1/3. Программа A
генерирует N точек в единичном квадрате и считает попадания под график.
Каждый поток накапливает свой счётчик и записывает итог в отдельную
ячейку общей памяти. Программа B суммирует результаты: I = hits/N.
Абсолютная ошибка = |I - 1/3|. Остаток от N/n распределяется по потокам.

Измерения выполнены 21.10.2026: Intel Core i5-12500H, 12 физических ядер,
16 логических CPU, 15,3 ГиБ RAM, Linux 7.0.0-38-generic, GCC 13.3.0,
-O2, pthread. CPU неоднородны: четыре ядра с двумя логическими CPU
и восемь с одним. Привязка потоков к ядрам не задавалась, режим powersave.

Серия 1: N = 500 млн точек, пять повторов. Серия 2: N = 20 млн, семь
повторов. В каждой серии один прогрев на конфигурацию, не включённый
в статистику. Все запуски последовательные; порядок конфигураций
в каждом повторе перемешивается с seed 20261021. Seed вычислений:
12345 + номер повтора с нуля, seed прогрева 1000000.
Таймер CLOCK_MONOTONIC охватывает создание потоков, вычисления и join.
Подготовка общей памяти и работа программы B в это время не входят.
В таблице медианы, ускорение T(1)/T(n) рассчитано отдельно для каждого N.

Все 180 запусков завершились успешно. Максимальная абсолютная ошибка
интеграла: 0,00005493 для 500 млн точек и 0,00025147 для 20 млн.
Это наблюдавшиеся значения, а не гарантированная граница ошибки.

Выводы
1. При 12 потоках (число физических ядер) ускорение равно 5,64 для
   большой серии и 5,53 для малой. Неоднородность ядер, создание потоков
   и планирование ограничивают рост; их вклад отдельно не измерялся.
2. При 500 млн точек после примерно 16 потоков рост почти прекращается:
   в диапазоне 16..512 время около 0,139..0,150 с. Минимальная медиана
   у 64 потоков, но 128 дают практически то же время, разброс пересекается.
   С 1024 потоков время растёт. При 4096 ещё есть ускорение 4,06 раза;
   проигрыш одному потоку для этого N в исследованном диапазоне не получен.
3. При 20 млн лучший результат у 16 потоков: ускорение 6,61.
   При 1024 потоках медиана ещё меньше однопоточной, при 2048 уже больше.
   По медианам переход находится между 1024 и 2048, точный порог не определён.
   У 2048 диапазон времён пересекается с однопоточным; при 4096 каждый
   повтор медленнее любого однопоточного, медиана 0,076410 против 0,036248 с.
4. Для небольшой работы создание большого числа потоков может стоить
   дороже выигрыша от параллельного расчёта. Порог зависит от N и машины.
   Внутри цикла нет общего mutex или общей изменяемой ячейки. Число
   потоков означает число созданных, не обязательно одновременно работающих.
