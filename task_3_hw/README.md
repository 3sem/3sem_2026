	# Задание 3: сравнение трёх способов IPC

Решение на C11 по [условию](../task_3/task.md): передача файла между двумя
процессами через разделяемую память SYS V, очередь сообщений SYS V и
именованный канал FIFO. Для каждой программы исследуются три размера
буфера; целостность проверяется MD5.

**Готовые результаты:** [отчёт с выводами и тремя гистограммами](REPORT.md),
[сырые измерения](results/measurements.csv),
[проверки корректности](VALIDATION.md).

## Сборка и отдельный запуск

```sh
cd task_3_hw
make
./ipc_info
./shm_transfer input.bin shm_output.bin 8192
./mq_transfer input.bin mq_output.bin 8192
./fifo_transfer input.bin fifo_output.bin 8192
md5sum input.bin shm_output.bin mq_output.bin fifo_output.bin
```

Одинаковая контрольная сумма у четырёх файлов означает успешную проверку.
На macOS без `md5sum` можно использовать `md5 -q имя_файла` для каждого файла.
Скрипт эксперимента автоматически выбирает `md5sum`, затем `md5 -q`,
а при отсутствии обеих утилит — Python `hashlib.md5`.

Интерфейс всех трёх программ:

```text
./<method>_transfer INPUT OUTPUT [BUFFER_BYTES]
method=shm bytes=268435579 buffer=8192 seconds=0.179766167
```

Последняя строка — пример формата результата, не обещание времени.
Буфер по умолчанию — 65536 байт; допустимый диапазон — от 1 до 16777216 байт.
Размер разделяемого сегмента дополнительно ограничивается настройками ОС:
ошибка `shmget` при превышении лимита возвращается пользователю.

Вход и выход должны быть разными обычными файлами. Существующий выходной
файл перезаписывается. Совпадение файлов проверяется по устройству и inode
**до** усечения, в том числе при жёсткой или символической ссылке.
При ошибке код возврата ненулевой, выход может быть неполным. Изменять
исходный файл во время работы нельзя. MD5 здесь выявляет ошибки передачи,
а не защищает от намеренной подмены.

## Повторение эксперимента

Для программ нужен C-компилятор и `make`; внешних C-библиотек нет.
Для проверок нужен Python 3.9+, для графиков дополнительно `matplotlib`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install matplotlib
make benchmark PYTHON=.venv/bin/python
```

Если Python с `matplotlib` уже установлен:

```sh
make benchmark
```

По умолчанию скрипт:

1. Определяет доступный размер сообщения SYS V и ёмкость FIFO.
2. Выбирает малый, средний и большой буферы на основании этих значений.
3. Создаёт случайный неразреженный файл размером 256 МиБ + 123 байта во
   временном каталоге. Дополнительные 123 байта проверяют последний неполный блок.
4. Выполняет по одному прогреву для всех девяти сочетаний и пять измеряемых
   повторов, перемешивая порядок в каждом раунде с фиксированным seed.
5. После **каждой** передачи, включая прогрев, сверяет размер и MD5.
6. Сохраняет параметры машины, CSV всех 45 измерений, медианы и графики
   в `results/`. Временные входной и выходной файлы удаляются автоматически.

Нужно около 513 МиБ свободного места для эксперимента по умолчанию.
Для нового эксперимента с другими параметрами и отдельной папкой результатов:

```sh
python3 scripts/benchmark.py --size-mib 1024 --repeats 7 --output-dir results_1g
python3 scripts/benchmark.py --input /path/to/large.bin --output-dir results_custom
```

`--buffers SMALL MEDIUM LARGE` задаёт три размера явно. Автоматически
выбранные размеры зависят от машины: значения из приложенного отчёта macOS
не следует механически переносить на Linux. Если автоматические размеры
совпали, скрипт попросит указать три различных размера вручную.

`results/shm.png`, `mq.png`, `fifo.png` — три гистограммы, каждая с тремя
столбцами по размерам буфера. Их PDF-версии подходят для печати.
`comparison.png` дополнительно показывает способы IPC на общей шкале.
Новый запуск в той же папке перезаписывает результаты эксперимента.

## Устройство решения

| Файл | Назначение |
| --- | --- |
| `sources/main.c` | Общая работа с файлами, `fork`, проверка размеров, время и завершение процессов |
| `sources/io.c` | Блочное чтение и полная запись с обработкой частичных операций и `EINTR` |
| `headers/transfer.h` | Общий интерфейс канала, непрозрачная структура `Channel` |
| `sources/shm.c` | `shmget`, `shmat`, два семафора SYS V |
| `sources/mq.c` | `msgget`, `msgsnd`, `msgrcv`, разбиение большого блока |
| `sources/fifo.c` | Передача через настоящий FIFO, созданный `mkfifo` |
| `sources/probe.c`, `ipc_info.c` | Определение лимитов и общее создание FIFO |
| `scripts/benchmark.py` | Измерения, MD5, CSV, статистика и графики |
| `scripts/test_transfer.py` | Проверки корректности и ошибок на настоящем IPC |

Собираются **три отдельных исполняемых файла** с общим `main.c` и разными
реализациями интерфейса `Channel`. Общие действия не копируются между ними.
Каждая передача создаёт ровно два процесса: родитель читает исходный файл
и отправляет данные, потомок принимает их и записывает выходной файл.

### Разделяемая память SYS V

`shmget(IPC_PRIVATE, ...)` создаёт сегмент: длина текущего блока и массив
данных размером `BUFFER_BYTES`. `shmat` подключает его до `fork`, поэтому
оба процесса получают доступ к одному сегменту.

Два семафора SYS V, созданные `semget`, задают протокол одного слота:

- `EMPTY_SLOT = 1`: отправитель может записать блок.
- `FULL_SLOT = 0`: получателю пока нечего читать.

Отправитель уменьшает `EMPTY_SLOT`, копирует данные и увеличивает `FULL_SLOT`.
Получатель уменьшает `FULL_SLOT`, копирует блок в свой буфер и увеличивает
`EMPTY_SLOT`. Только после этого отправитель вправе перезаписать сегмент.
`semop` обеспечивает синхронизацию; `sleep`, активного ожидания и гонки
на флаге готовности нет. Нулевая длина означает конец файла.

В реализации есть копирование из локального буфера в сегмент и обратно:
это не zero-copy. На малых блоках существенна цена четырёх операций `semop`
на блок, на больших их число уменьшается.

### Очередь сообщений SYS V

Используются именно `msgget`/`msgsnd`/`msgrcv`, а не POSIX `mq_open`.
Все сообщения имеют положительный тип `1`; поле типа `long` не включается
в параметр длины сообщения. Нулевой размер данных обозначает EOF.

Большой пользовательский буфер разбивается на сообщения не длиннее
доступного лимита. Получатель собирает их в блоки своего пользовательского
буфера и записывает блок целиком. Поэтому параметр `BUFFER_BYTES` одинаково
задаёт размер файлового ввода-вывода во всех трёх программах, но **не снимает
системное ограничение на размер одного сообщения**.

Перед измерением в собственной пустой очереди двоичным поиском определяется
наибольшее допустимое сообщение, ограниченное также `msg_qbytes` и 16 МиБ.
Это эффективный лимит для данной очереди, не обязательно сырой `MSGMAX` ОС.
Системные настройки и ёмкость очереди программа не меняет.

### Именованный FIFO

`mkdtemp` создаёт приватный каталог, `mkfifo` — FIFO внутри него. До `fork`
открываются оба конца в неблокирующем режиме, чтобы открытие не зависело
от порядка запуска процессов. Имя удаляется после открытия: FIFO продолжает
существовать, пока открыты его дескрипторы. Это файловый объект FIFO,
не вызов `pipe()` и не обычный файл для обмена данными.

После `fork` каждый процесс закрывает ненужный конец, оставшийся переводит
в блокирующий режим. FIFO передаёт поток байтов; короткие `read`/`write`
обрабатываются циклами. Закрытие единственного писателя служит EOF.

На Linux ёмкость определяется через `F_GETPIPE_SZ`. Если его нет, отдельный
FIFO заполняется неблокирующими записями по 4096 байт до `EAGAIN`.
Это наблюдаемая ёмкость в условиях пробы. ОС может динамически изменять
буфер FIFO. `PIPE_BUF` описывает атомарность записи, а не его общую ёмкость.

### Завершение и большие файлы

Счётчики используют `uint64_t`, файловые смещения — 64-битные при наличии
поддержки `_FILE_OFFSET_BITS=64`. Потребление памяти — `O(BUFFER_BYTES)`;
файл целиком в оперативную память не загружается. Вход и принятый поток
проверяются по ожидаемому размеру, содержимое отдельно проверяется MD5.

Родитель ожидает потомка через `waitpid`, проверяет его статус, удаляет
очередь/семафоры/сегмент SYS V и закрывает свои дескрипторы. При ошибке
отправителя родитель прекращает работу собственного потомка и дожидается
его. `SIGINT`, `SIGTERM`, `SIGCHLD` прерывают ожидание; редкий `SIGALRM`
устраняет гонку между проверкой завершения потомка и блокирующим вызовом.
`SIGPIPE` игнорируется, чтобы получить обрабатываемую ошибку `EPIPE`.
Принудительное убийство родителя через `SIGKILL` не позволяет выполнить
очистку SYS V; для прерывания используйте Ctrl+C или `SIGTERM`.

## Что входит во время

`CLOCK_MONOTONIC` измеряет интервал непосредственно перед `fork` и до
возврата `waitpid`, после закрытия получателем выходного файла.
Включены `fork`, чтение исходного файла, IPC, запись выходного файла и
завершение потомка. Создание IPC, определение лимитов, подготовка файла,
MD5 и построение графиков не включены. Границы интервала одинаковы для
всех трёх программ.

`fsync` не вызывается. Замер характеризует передачу с участием файлового
кэша ОС, а не гарантированное сохранение на физический накопитель.
Контрольная сумма входа и прогрев читают файл перед измерениями; сброс
кэша, закрепление за ядрами и изменение приоритетов не применяются.
Для интерпретации сравнивайте медианы и разброс; результат зависит от ОС,
нагрузки, реализации синхронизации и системных лимитов.

## Проверки

```sh
make test
python3 scripts/test_transfer.py --large --report results/validation.json
```

`--large` дополнительно передаёт каждым способом файл **4 ГиБ + 12345 байт**.
Он разреженный, с ненулевыми случайными участками, в том числе на границе
2³² байт; выход записывается обычным `write`. Нужны примерно 4.1 ГиБ
свободного места. Этот тест проверяет счётчики и целостность, но его время
не используется в сравнении производительности.
