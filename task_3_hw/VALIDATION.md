# Проверки решения

Проверено 21 октября 2026 года на macOS 26.6.2, arm64,
Apple Clang 17.0.0, Python 3.13.5. Сборка `make -j4` с
`-O2 -std=c11 -Wall -Wextra -Wpedantic` прошла без предупреждений.
SYS V IPC и FIFO использовались настоящие, без имитации.

## Автоматические проверки

Команды из каталога решения:

```sh
make
python3 scripts/test_transfer.py --report results/validation.json
python3 scripts/test_transfer.py --large --report results/validation.json
```

Обе проверки завершились `All tests passed.`. Второй запуск повторил
обычные проверки и дополнительно проверил большие файлы. Его результат
сохранён в [results/validation.json](results/validation.json).

Для каждого из трёх способов выполнено 19 основных проверок целостности:

- Для буферов 2048, 8192 и 1048576 байт: файлы длиной 0, 1, `B - 1`, `B`
  и `B + 1` байт, где `B` — размер буфера.
- Файл 10003 байта с буферами 1 и 17 байт.
- Файл 3145865 байт с буферами 2061 и 65537 байт. Это проверяет разбиение
  очередью блоков, не кратных максимальному сообщению.

Проверялось совпадение MD5 и независимое побайтовое равенство, размеры
файлов, счётчик переданных байтов, имя метода и размер буфера в результате.
Выходной файл перед передачей содержал старые данные, поэтому проверялось
и его правильное усечение. Использовался путь с пробелами.

Отдельно для каждого способа проверены:

- Отказ при одинаковом входе и выходе, включая жёсткую и символическую
  ссылки; исходные байты сохранились.
- Отказ для размеров `0`, `-1`, `abc`, `16777217`, слишком длинного числа,
  пустой строки, строки с начальным пробелом и `+1`.
- Отсутствующий вход, каталог вместо входа или выхода, отсутствующий
  родительский каталог выхода.
- Принудительный отказ записи у получателя: `RLIMIT_FSIZE = 4096` при
  передаче файла 4194317 байт. Родитель завершился с ошибкой, зависания
  не было; тайм-аут проверки — 8 секунд.
- Повторная успешная передача после такого отказа с буфером 1 МиБ,
  снова с MD5 и побайтовым сравнением.

## Файл больше 4 ГиБ

Размер: **4294979641 байт**, то есть 4 ГиБ + 12345 байт.
Размер пользовательского буфера: **1048576 байт** для каждого способа.

Вход разреженный: нулевые области и случайные участки по 4096 байт
в начале, непосредственно перед границей 2³² байт и в конце. Все байты
читаются и передаются через IPC; выход создаётся обычными `write`,
разреженные области в нём программно не создаются.

| Способ | Передано и записано, байт | Время, с | MD5 выхода |
| --- | ---: | ---: | --- |
| SYS V shared memory | 4294979641 | 1.899995 | `581c836714c826616279568e981a1a12` |
| SYS V message queue | 4294979641 | 25.080351 | `581c836714c826616279568e981a1a12` |
| FIFO | 4294979641 | 2.583156 | `581c836714c826616279568e981a1a12` |

MD5 входа: `581c836714c826616279568e981a1a12`.
Этот тест подтверждает передачу за границей 32-битного счётчика, но его
времена не используются в эксперименте производительности: вход разреженный.

## Основной эксперимент

Команда `python3 scripts/benchmark.py` успешно выполнила 9 прогревов и
45 измеряемых передач случайного неразреженного файла 268435579 байт.
MD5 совпал во всех запусках. Три гистограммы и их PDF-версии построены
по сохранённому CSV. Результаты и границы интерпретации приведены в
[REPORT.md](REPORT.md).

## Границы проверки

Запуски выполнены на macOS. Для Linux я предусматривал, но не уверен, заведётся или нет. Измерения не включают `fsync` и не подтверждают физическую
запись на накопитель
