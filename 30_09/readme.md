# Monte Carlo: многопоточное вычисление интеграла

Программа вычисляет интеграл

$$
I=\int_0^1 x\,dx=\frac{1}{2}
$$

методом Монте-Карло. Программа A распределяет генерацию случайных точек между потоками и сохраняет результаты в разделяемой памяти System V. Программа Б считывает результаты и вычисляет приближение интеграла.

Сравниваются два режима:

- `per_thread` — отдельный счётчик попаданий для каждого потока;
- `shared_mutex` — общий счётчик, защищённый мьютексом.

## Требования

Linux, CMake, GCC или Clang, Python 3 и `matplotlib` для построения графиков.

Для Ubuntu необходимые инструменты можно установить командой:

```bash
sudo apt update
sudo apt install build-essential cmake python3 python3-matplotlib
```

## Сборка

Из корня проекта `30_09/` выполните:

```bash
cmake -S . -B build-benchmarks -DBUILD_BENCHMARKS=ON
cmake --build build-benchmarks --parallel
```

## Запуск эксперимента

Для воспроизведения расширенной серии с 20 миллионами точек, тремя повторениями и количеством потоков от 1 до 2048:

```bash
POINTS=20000000 \
REPEATS=3 \
THREAD_COUNTS="1 2 4 8 12 16 24 32 48 64 96 128 256 512 1024 2048" \
cmake --build build-benchmarks --target run_experiments
```

Число точек $N$ остаётся одинаковым во всех запусках. Перед экспериментом рекомендуется закрыть приложения, создающие существенную нагрузку на процессор.

## Результаты

Результаты сохраняются в каталоге `benchmarks/`:

- `results.csv` — время выполнения, количество попаданий, оценка интеграла и абсолютная погрешность;
- `thread_scaling_time.png` — зависимость времени вычислений от числа потоков;
- `thread_scaling_speedup.png` — ускорение относительно однопоточного выполнения.

Графики строятся автоматически при наличии `matplotlib`. Повторный запуск перезаписывает предыдущие результаты, поэтому нужные файлы следует сохранить заранее.

## Методика измерений

Время измеряется с помощью `clock_gettime(CLOCK_MONOTONIC, ...)` от начала создания потоков до завершения всех потоков через `pthread_join()`. Подготовка разделяемой памяти и обработка результата программой Б в измеряемый интервал не входят.

Ускорение определяется как

$$
S(n)=\frac{T(1)}{T(n)},
$$

где $T(1)$ — время выполнения одним потоком, а $T(n)$ — время выполнения $n$ потоками в том же режиме хранения.

При идеальном масштабировании ускорение равно числу потоков:

$$
S_{\mathrm{ideal}}(n)=n.
$$

Фактическое ускорение может быть ниже из-за накладных расходов на создание и планирование потоков, а также из-за синхронизации при использовании общего счётчика.

Оценка интеграла рассчитывается как

$$
\hat I=\frac{H}{N},
$$

где $H$ — общее количество точек, удовлетворяющих условию $y\leq x$, а $N$ — общее число сгенерированных точек.

Абсолютная погрешность относительно аналитического значения равна

$$
\Delta=\left|\hat I-\frac{1}{2}\right|.
$$

Эксперимент позволяет сравнить масштабируемость двух способов хранения результатов и определить, при каком количестве потоков рост производительности замедляется или сменяется снижением производительности.
