# IPC: сравнение способов передачи файлов

## Требования

Для запуска необходим Linux, CMake, C-компилятор, Bash, Python 3 с библиотекой `matplotlib`, а также утилиты `md5sum`, `ipcs`, `ipcrm` и `timeout`.

## Сборка и запуск

```bash
cmake -S . -B build -DBENCHMARKS=ON
cmake --build build --parallel
sudo -v
cmake --build build --target run_benchmarks
```

Скрипт последовательно проведёт измерения для файлов размером 512 МиБ, 1 ГиБ и 2 ГиБ.

Для каждого размера файла проверяются три механизма IPC:
- System V shared memory;
- System V message queue;
- FIFO.

Для каждого механизма используются три размера буфера: Small, Medium и Large. Каждый сценарий выполняется один раз для прогрева и пять раз для измерений. Порядок сценариев перемешивается.

## Результаты

Результаты автоматически сохраняются в каталог `results/`:

```text
results/
├── 512MiB/
├── 1GiB/
└── 2GiB/
```

В каждой папке создаются:
- `results.csv` — результаты измерений и MD5 входного и выходного файлов;
- `transfer_times.png` — график сравнения времени передачи;
- `input.bin` — входной файл для соответствующей серии.

Для проверки корректности передачи сравниваются MD5 входного и выходного файлов. При несовпадении хешей измерение считается неуспешным.

## Методика измерения

Время измеряется с помощью встроенной команды `time` Bash вокруг функции `run_transfer`. Оно включает запуск процессов, синхронизацию, передачу данных, запись выходного файла и завершение процессов.

В CSV сохраняются три показателя: `real_seconds` — реальное прошедшее время, `user_seconds` — процессорное время в пользовательском режиме и `system_seconds` — процессорное время в режиме ядра.

Графики строятся по `real_seconds`: для каждого сценария показываются медиана пяти измерений, интерквартильный диапазон и отдельные результаты.

Проверка MD5 выполняется после измеряемого интервала. Принудительная синхронизация выходного файла с накопителем через `fsync()` не используется, поэтому измерение не гарантирует физическую запись всех данных на диск.

Скрипт при необходимости временно увеличивает системные лимиты очереди сообщений System V и пытается восстановить их исходные значения после завершения.
