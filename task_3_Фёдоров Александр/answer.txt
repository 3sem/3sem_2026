Задача 3. Сравнение способов межпроцессного взаимодействия

Реализованы три программы передачи файла между двумя процессами:
shm.c — разделяемая память SYS V, общий буфер и два семафора;
mq.c — очередь сообщений SYS V;
fifo.c — именованный канал FIFO.
Родитель читает исходный файл, потомок получает данные и записывает их.
Общие функции чтения, записи и измерения времени находятся в common.h.

Условия эксперимента

Передавался двоичный файл размером 536 870 929 байт (512 МиБ + 17 байт).
Система: macOS, Darwin 25.5.0, arm64. Компилятор Apple Clang, оптимизация -O2.
Для каждого способа и размера буфера сделано три измерения — всего 27.
Порядок запусков перемешан с seed 42. Перед серией прочитан исходный файл
для MD5 и выполнен один разогревочный запуск каждого способа.

Время измеряется через CLOCK_MONOTONIC и включает fork, чтение файла,
передачу, запись и ожидание потомка. Подготовка IPC и проверка MD5 исключены.
fsync не вызывается: запись может завершаться в файловом кеше.

Выбраны три размера буфера:
2048 байт — доступный размер полезных данных сообщения при текущих лимитах;
8192 байт — измеренная ёмкость FIFO при заполнении без чтения;
262144 байта — в 32 раза больше ёмкости FIFO.

На этой машине msg_qbytes новой очереди равен 2048 байт. Поэтому блоки
8 и 256 КиБ разбиваются на сообщения до 2048 байт, а получатель собирает
их перед записью. Размер логического блока не равен размеру сообщения.
Ёмкость очереди и максимальный размер сообщения — разные ограничения.
Системные настройки не менялись.

Результаты

Медианное время передачи, секунды:
Способ                       2 КиБ       8 КиБ     256 КиБ
SYS V shared memory      2.897597    1.142904    0.752446
SYS V message queue      7.807653    7.164183    6.437731
FIFO                     1.478008    0.771140    0.600751

В graphs.png приведены три диаграммы. Высота столбцов — медиана,
усы — минимум и максимум трёх запусков, а не доверительный интервал.

MD5 исходного файла: b9571fc90f26edb57bd2b95543090000.
У всех 27 полученных файлов MD5 и размер совпали с исходным файлом.

Выводы

1. FIFO показал наименьшую медиану при всех трёх размерах буфера.
   При увеличении буфера с 2 до 256 КиБ время уменьшилось в 2.46 раза.
2. Для разделяемой памяти ускорение составило 3.85 раза. Крупные блоки
   уменьшают число операций синхронизации на тот же объём данных.
3. Очередь сообщений оказалась самой медленной. Увеличение логического
   блока дало ускорение в 1.21 раза, но сами сообщения остались по 2048 байт.
   Сократилось число файловых чтений и записей, а не число сообщений.
4. При 256 КиБ диапазоны времени разделяемой памяти и FIFO пересекаются.
   Выводы относятся к этим реализациям и измерениям на macOS; результат
   зависит от машины, лимитов IPC и файлового кеша.

Сборка и запуск из папки с исходниками:
cc -std=c11 -Wall -Wextra -Wpedantic -O2 shm.c -o shm
cc -std=c11 -Wall -Wextra -Wpedantic -O2 mq.c -o mq
cc -std=c11 -Wall -Wextra -Wpedantic -O2 fifo.c -o fifo
./shm input.bin out-shm.bin 8192
./mq input.bin out-mq.bin 8192
./fifo input.bin out-fifo.bin 8192

Последний аргумент — размер буфера в байтах. Выходные файлы должны быть новыми.
Проверка контрольных сумм на macOS:
md5 input.bin out-shm.bin out-mq.bin out-fifo.bin
На Linux вместо md5 используется md5sum.
